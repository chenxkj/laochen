# 抖音·播放量预测 Skill（v5.3）

> **职责边界**：只做传播预测。不评选题，不评内容
> **触发词**：预测一下/能火吗/传播预测
> **唯一性**：本skill是内容类型基准表和预测公式的**唯一来源**，topic-research调用时引用此处

---

## 一、触发条件

选题评审第4关 / 问"能火吗" / 数据复盘回溯偏差

---

## 二、输入

内容类型 + 时长 + 细分类型(冲突/共情/干货) + 逐字稿 + 当前粉丝数

---

## 三、输出

1. 内容类型基准判断 + 预测字段表(6-7项)
2. 冷启动修正后结果
3. 置信度（高/中/低）

---

## 四、短视频预测（<3min）

### 4.1 内容类型基准（唯一来源）

| 类型 | 完播率基准 | 播放量参考 | 案例 |
|:-----|:---------:|:----------|:-----|
| 强情绪+冲突(25-30s) | **10-15%** | 1-2万 | 第11/25期 |
| 强情绪+冲突(35-45s) | **8-12%** | 5k-1.5万 | 第25期 |
| 身份标签+强钩子(>40s) | **4-6%** | 2-4万 | 第1/15期 |
| 感悟/金句型 | **3-7%** | 500-2000 | 第19期 |
| 汇报/复盘型 | **3-4%** | 300-1000 | 第21期 |
| 方法论/干货型 | **2-5%** | 500-2000 | 第12期 |

### 4.2 预测公式

```
最终预测 = 基准 × 分享率系数 × 情绪强度系数

分享率系数：有"让XX看到这个"动机 → ×1.5；无 → ×0.5
情绪强度系数：有真实时刻/冲突对话 → ×1.3；弱 → ×0.8
```

### 4.3 冷启动修正（粉丝<500时必执行）

> 来源：第28期教训——预测153实际153看似准确，实则<500粉时自然流量极低，真实偏差>99%

```
修正后 = 最终预测 × 系数
  方法论/干货 → ×0.3
  强情绪类 → ×0.4
  身份标签+故事 → ×0.5
```

> 不执行 → 预测偏差>50%，作废。

### 4.4 三情景预测（v5.5新增·防止过度乐观）

> **核心问题**：预测用"理论最优"当基线，忽视账号现实。导致预测8000-20000，实际只有43-835。
> **解决**：必须计算3个情景，悲观情景<500→重新考虑是否值得拍。

| 情景 | 公式 | 说明 |
|:-----|:-----|:-----|
| 悲观 | 账号中位数 × 0.5 | 如果账号中位数是1248，悲观=624 |
| 中性 | 账号中位数 × 1.0 | 1248 |
| 乐观 | 账号中位数 × 2.0 | 2496 |

**判定规则**：
- 悲观情景 < 500 → ⚠️ 必须重新考虑是否值得拍，或降低预期
- 中性情景 < 1000 → 不值得精细制作（用手机随手拍降低成本）
- 乐观情景 < 3000 → 不要预期"爆款"，定位为"测试反馈"

**输出必须包含3个情景**，不能只报乐观预测。

### 4.5 预测字段（每期必填）

| 维度 | 指标 | 预测值 | 依据 |
|:-----|:----:|:------:|:-----|
| 完播率 | 5秒完播 | ___% | 钩子×类型基准 |
| 完播率 | 整体完播 | ___% | 类型基准 |
| 播放量 | 基准预测 | ___ | 类型基准 |
| 播放量 | 修正后 | ___ | 前值×系数(___) |
| 分享率 | ___% | — | "转给XX"动机 |
| 涨粉 | ___ | — | 系列钩子? |

## 四附、概率分布与反事实场景（吸收自CHEAT·v5.4增补）

> **根因**：只给单一预测值（如"修正后播放量：___"）是false precision——小样本下AI无法精确预测。
> **解决**：给出所有bucket的概率分布（相加=100%），强迫诚实；同时写反事实场景，供复盘时验证。

### 4.附.1 播放量bucket划分（自动派生）

基于账号历史数据（≥3条有实绩）自动派生；不足3条时用平台通用默认。

**派生算法**（参考CHEAT `cheat-bump` Phase B）：
- `baseline = median(历史播放量)`
- bucket边界：`baseline × {0.3, 1, 3, 10}`（ratio模式，N≥3）；或percentile `{30, 60, 85, 95}`（N≥10）

**默认bucket**（冷启动<3条历史）：

| bucket | 范围 | 说明 |
|:-----|:-----|:-----|
| 底部 | < 账号中位数×0.3 | 严重翻车 |
| 基础盘 | 账号中位数×0.3 ~ ×1 | 正常表现 |
| 命中 | 账号中位数×1 ~ ×3 | 超出预期 |
| 小爆 | 账号中位数×3 ~ ×10 | 可被传播 |
| 现象级 | > 账号中位数×10 | 模因级 |

**写入位置**：预测字段表之后、置信度之前。

### 4.附.2 概率分布输出（强制·不可省略）

**强制规则**：必须给出所有bucket的概率，**相加=100%**。不允许"95%中枢+5%其他"这种偷懒写法。

**概率分布反映置信度**：
- 置信度高 → 分布集中（如：基础盘45% / 命中40% / 其他15%）
- 置信度低 → 分布平坦（如：底部20% / 基础盘25% / 命中30% / 小爆20% / 现象级5%）

输出格式（接在预测字段表之后）：

```
🎯 bucket押注：命中（中枢 ~X）
   概率分布：底部 __% / 基础盘 __% / **命中 __%** / 小爆 __% / 现象级 __%
   （相加=100% · 置信度：高/中/低）

🔍 锚点对比：
| 对照 | 实绩bucket | 与本次差异 |
|:-----|:---------|:----------|
| [同类时长+composite±0.5的已发视频] | [bucket] | [差异分析] |
| [如有] | ... | ... |
（锚点不足2个 → 注明"锚点N/A，中枢±25%")

🤔 反事实场景：
- 如果落在**小爆** → 验证：[具体假设，如"ER主导+MS触发扩散"]
- 如果落在**基础盘** → 说明：[具体假设未触发，如"话题冷启动无传播势能"]
- 如果落在**底部** → 推翻：[具体假设，如"钩子强度被高估"]

🎲 关键校准假设：本篇 vs [对照视频名称] = X.Xx
（明确写：我押这次比上次[高/低]多少倍，复盘时验证）
```

### 4.附.3 反事实场景的复盘用途

**写入预测文件后，这段文字是immutable的**（见第八节盲预测铁律）。

复盘时（调用`douyin-data-review`）：
1. 实际bucket命中 → 读出对应反事实场景 → 验证/推翻假设
2. 如果实际与所有反事实都不符 → 说明rubric漏了维度，写入"待观察"
3. 关键校准假设被验证 → 写入`rubric_notes.md`的"观察记录"

**没有反事实场景 → 复盘退化为"准/不准"的模糊判断，无法改进rubric**。

## 五、长视频预测（≥3min）

### 5.1 基准

| 类型 | 完播率基准 | 播放量参考 | 核心指标 |
|:-----|:---------:|:----------|:---------|
| 搜索驱动型(教程) | 15-25% | 500-3000 | 收藏率>搜索排名 |
| 深度干货型(合集) | 10-20% | 300-2000 | 追更率+收藏率 |
| 身份+干货型 | 8-15% | 500-5000 | 搜索+信任 |
| 方法论清单型 | 5-12% | 200-1500 | 收藏率 |

### 5.2 公式

```
最终预测 = 基准 × 收藏系数 × 系列系数 × 搜索系数

收藏：有清单/框架 → ×1.5；无 → ×0.5
系列：有明确下期预告 → ×1.3；无 → ×0.8
搜索：标题含搜索词 → ×1.5；无 → ×0.6
```

### 5.3 冷启动修正（长视频因搜索加持，系数+0.1）

方法论清单→×0.4 / 深度干货→×0.5 / 搜索驱动+身份→×0.6

### 5.4 长视频预测字段

|:-----|:----:|:------:|:-----|
| 完播率 | 30秒留存 | ___% | 前30s钩子强度 |
| 完播率 | 整体完播 | ___% | 类型基准 |
| 播放量 | 修正后 | ___ | 基准×三系数×冷启动系数 |
| 收藏率 | ___% | — | 清单/框架? |

## 纪律

1. **不评选题**：只出预测数据
2. **不评内容**：归scoring skill
3. **冷启动必执行**：<500粉不修正→作废
4. **历史优先**：有历史数据必须引用
5. **⛔ 完播率预测强制均值校准**：预测整体完播时，基线 ≤ 账号完播均值 × 1.5（当前≈7.66% × 1.5 = 11.5%）。超过此值必须手动标注理由（如"本期有特殊传播结构支撑"），否则视为预测无效
6. **⛔ 播放量锚点禁用单条爆款**：预测锚点必须取该品类≥3条近期视频的平均值。禁止以单条偶发爆款（如第27期/第1期）作为锚点基数

---

## 八、盲预测铁律（吸收自 cheat-on-content 原则 #1）

> 核心目的：防止事后"合理化"，保持预测的真实校准价值

**三条强制规则**：

1. **发布前写定**：预测字段必须在视频发布**之前**填写完毕。发布后填写的"预测"作废，记为 `reconstructed`（重构预测），不纳入校准池
2. **发布后不可修改**：预测一旦写入方案文件，不得修改。只能在"复盘"段追加"我当时判断错在哪"
3. **偏差必须记录**：每次复盘发现预测偏差>30%，必须写明偏差原因并更新第七节校准记录

**违反处理**：
- 已知结果后写的"预测"→ 标注`[reconstructed]`，不计入历史校准数据
- 要修改预测→ 新建一条`_redo`记录，保留原预测文件

**盲预测的意义**：
> cheat-on-content 的数据显示：不执行盲预测的账号，其"预测能力"随时间不升反降——因为每次"事后合理化"都在强化错误的直觉校准。只有盲预测-复盘闭环才能让预测越来越准。
